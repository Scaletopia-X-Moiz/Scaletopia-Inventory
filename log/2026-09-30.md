# 2026-09-30

- Built the GHL "Last activity" feature end to end on `feat/ghl-last-activity`: a
  new `ghl_messages` history table, four denormalized columns on
  `platform_pushes`, an incremental sync that sweeps a sub-account's
  conversations and only re-reads contacts whose activity actually moved, a
  People-table column with GHL-matching truncated relative time, a click-through
  message-history drawer, a client-scoped filter (is empty / is not empty /
  between / within last N days), and a background Refresh button.
- The sync rides the existing `push_jobs` queue as platform `ghl_activity`
  rather than a parallel queue, so it shares the per-client serialization a push
  already has — the two hit the same GHL location's rate limit.
- The filter deliberately touches none of the six filter RPCs; it resolves an id
  set off `platform_pushes` the way the `pushJobId` filter does. See
  `lib/data/ticket-25-esp-filter.sql:23-31` for the regression that made that
  the right call.
- Found and left open: the one client with real pushed GHL contacts (`testing`)
  still holds a stale contacts-only token that 401s on every conversations
  endpoint. It needs re-issuing before the feature is useful in production.
- Full write-up in `docs/features/ghl-last-activity/handoff.md` §14.
